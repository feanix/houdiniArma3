# Release plan (#228)

Where the plan lives: the `target_release` column on tasks (schema V23). Nothing else stores it.

- Place: `python -m aesir --as advisor task set N --release 0.18.0` (`none` clears). The advisor places per the decisions; the lead applies them. Every change is a task_log line and an event with the actor.
- View: `python -m aesir release plan [--json]`. Order inside a release follows `task link A after B`. `(ready to tag)` = every task merged/verified (wontfix does not block). `missed X.Y.Z` = open task in a release already tagged: move it or close it.
- File: `ROADMAP.md` at the repo root is generated by each state export (`export`, and the merge queue's `Merge #N ...; state export` commit). Never edit it; the header says so. Same plan, same bytes.
- Upstream: `python -m aesir upstream sync-milestones` shows what it would do; `--apply` creates/updates milestone `Aesir X.Y.Z` and sets it on each linked report. A report linked to tasks in two releases takes the earliest. Run it by hand after changing the plan; hooks never call it.
- The plan is a plan, not a promise: a decision records why a task moved.
