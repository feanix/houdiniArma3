# Changelog

Agent-facing: read the entries between your pinned version and the one you upgrade to.

## 0.18.1 (2026-11-03)

Client actions: run `upgrade` (no schema change), then restart sessions so agents load the new reviewer def. `queue run` now waits for the machine gate lock without a limit by default: set `[queue] lock_wait` (seconds, 0 = no limit) or pass `--lock-wait` if a run must give up. Client leads: add `--name <agent name>` to `spawn-context` calls to get the exact scratch folder path.
Gate lock relief (D239): the queue waits its turn instead of giving up 'busy'; every lock wait and give-up is recorded (`gate lock-stats [--since D]`); every gate run prints `lock wait Ns; steps: <step> Ns, ...; run Ns`.
Fewer repeat gate runs: the merge queue reuses a passing full gate on the same tree; in_review accepts a tier already passed at the head (`evidence add --reuse`); reviewers reuse a passing quick gate at the head and gate only on APPROVE.
Hooks: a subagent's hooks judge against its own project's db, so a `cd` into another folder no longer drops guards; no findable db = denied.
Scratch: a task-bound agent's scratch folder is kept until its task closes (cap `[scratch] keep_bound_days`, default 14). status runs far fewer git calls.
- The reviewer def no longer re-runs the quick gate when the branch head already has a passing one (reports#144 part 1): it decides the verdict from code, tests and evidence first and gates only on APPROVE when none exists at the head or the brief asks. `spawn-context reviewer` prints `Gate state: quick gate PASS at <sha> (gate run <id>)` or `no gate at head <sha>`; new shared `gates.passed_at_head` returns the passing run of a tier or higher at an exact sha.
- Merge queue reuses a gate already passed on the same tree (#244, reports#152 part a): when the merge commit's tree equals the tree of a recorded passing `full` gate run (a quick run does not count; tier order is `gates.SATISFIES`), the queue records a reused run on the merge commit instead of rerunning the gate, and says so (`reused gate run N (full, tree T)`) in its output and task log. A different tree runs the gate as before.
- `in_review` reuses a gate tier already passed at the branch head (reports#159): a criterion citing "full tier" / "quick gate" / "full suite" is met by that passing gate run (state `gate`, via the shared `gates.passed_at_head`); if the head moved, the refusal names both shas ("full gate passed at A but the head moved to B: rerun it"). `evidence add --criterion C --reuse E<id>|gate:<id>` records an executed row copying a run that passed at the current head, so one run backs several criteria with no rerun (refused at a moved head, naming both shas, for a failed, note or must-fail source); the source's expect is never copied, so the row is RAN unless `--expect TEXT` matches the source's output (then MET). A tier counts only when cited as passing ("the full tier passes"), never for must-fail or ui criteria. Notes are unchanged.
- status: one worktree scan and one transcript scan per run, shared by every section; the merged check is one `git for-each-ref --merged` for all branches; only worktrees of merged/verified/wontfix tasks are examined, so git calls no longer grow with the worktree count (224 down to 3 on this repo; the run took 77-120s under gate load) (#272)
- A task-bound agent's scratch folder is kept after a clean finish until the task is merged, verified or wontfix, so a later agent of the same workflow can read the extracts (reports#175); failed ones also wait out keep_failed_hours, unbound agents and tasks that cannot be read keep the old hours rule. The scratch line in spawn-context and whoami states the actual lifetime; the researcher def says shared outputs go in the task's docs/.
- `spawn-context --name <agent name>` (#275 c7): a lead who passes the spawn prompt's Agent name gets the exact `Scratch folder:` path and its lifetime before the agent exists, and the scope hook allows a first write there; client leads should add `--name <agent name>` to their spawn-context call. Without `--name` the line shows the path form `<temp>/aesir/<project>/<your Agent name>/`.
- A bound folder is capped by the new `[scratch] keep_bound_days` (default 14, D234): swept at that age even while its task is open (running agents never). `spawn-context --name X` no longer answers with another live agent's id and folder when no row is named X.
- hooks: a subagent's hook judges against its own project's db (CLAUDE_PROJECT_DIR, else the payload cwd), not the db found from the tool call's cwd, so a `cd` into a folder with no db or a temp/foreign Aesir project no longer drops pkill, `--as`, AESIR_AGENT, main-checkout redirect and HEAD-move guards; a subagent with no findable db is denied (shell and edit tools) instead of unguarded; --db / AESIR_DB keep precedence (#279)
- Gate lock relief (D239): `queue run` waits its turn for the gate lock (progress line at most once a minute; `[queue] lock_wait` caps it, `--lock-wait` too) instead of giving up at `[gate] lock_wait`. Every lock wait and give-up is a `gate/lock wait` event; `gate lock-stats [--since D]` summarises them per project. Gate runs print `lock wait Ns; steps: ...; run Ns` (also in the gate tail, task log and queue log line).

## 0.18.0 (2026-11-03)

Client actions: run `upgrade` (db schema 24: evidence mutation checks), then restart sessions; `upgrade` regenerates the agent defs (example commands the guards allow; test command from your aesir.toml [gates]), and running agents keep the old defs until restarted.
Guards (subagent Bash): a command the parser cannot read is refused up front with the reason (D221); heredoc tags built from glued pieces are refused; `<<<` is a here-string; '>' inside a quoted heredoc body fed to cat/tee, '>=' comparisons, '>|' and ANSI-C targets are judged correctly. Known limits, refused for now and named in the refusal: a quote inside a # comment, $(( )) with << (fix planned, #271).
Queue: holds a schema-bump merge while running agents are on an older schema (`--force-schema-hold --reason` for the lead); merges only the approved head (origin head when the local ref lags); cleanup no longer reports an unregistered worktree as left in place and still deletes the merged branch.
Evidence: argument vectors run without a shell; .sh by path on Windows runs faithfully; a command that did not run never records a pass; --expect-fail mutation checks.
Tasks/scope: space-separated scope entries; a warning when an entry matches no path; folder scope covers its Rust module root; in_review staleness names the ref and sha and uses the pushed head; `gate run` without --task credits the task by head.
Resume/status: done tasks left in_progress shown once with the requester's close command; ended agents shown ended; old stalls collapsed (`status ack --older-than`); the size warning measures the session it runs in. Spawn prompt `Agent name:` is used whatever its prefix; role comes from the agent type.
Release: an issue with an open linked task is partial, not fixed; `upstream unlink`, `fixed-in --skip`. No silent empty db outside a project.
- `evidence run -- <cmd> <arg>...` with two or more arguments now runs the argument vector directly with no shell, so `^ ( ) & < > |` inside an argument stay literal (`git grep -E "a|b"`); a single-string command still runs through the shell (cmd.exe on Windows, /bin/sh elsewhere, named in `--help`); the recorded `cmd:` quotes each argument as executed; on Windows an argv starting with `bash`, `sh` or a `.sh` path resolves Git for Windows bash whatever shell called aesir (#191, aesir-reports #70). Two or more words now run without a shell; to keep shell features (`&&`, `|`, `>`, `;`) pass the whole command as one quoted string. On Windows a first word that is not a program (a cmd builtin) goes through cmd.exe with metacharacters caret-escaped.
- The SessionStart size warning now measures the starting session's own transcript; a fresh session with no usage yet gets no warning instead of the previous session's size (reports#100).
- `evidence run`: a command that exits non-zero with no output records `[no output captured: exit N; cwd ...; shell ...]` instead of a bare `[exit 1]`, so a silent failure names where and how it ran (#200, aesir-reports #111; the original `cargo fmt --check` case did not reproduce on current code).
- Task scope: a plain directory entry `src/persist` also covers the Rust module root file `src/persist.rs` (exact name; `src/persist/mod.rs` was already inside the folder) in the edit hook, in_review check and merge queue (#201, reports#112).
- in_review judges a task branch by one resolved head: `origin/<branch>` when the local ref is an ancestor of it (a fix round pushed from another worktree), else the local ref. The evidence-staleness, quick-gate, scope / out-of-scope, docs-only and `--base-task` readers all use it (aesir-reports#119, #139). The `(stale)` refusal now names the ref, its head sha and each stale criterion's newest evidence sha.
- `gate run` without --task credits the task whose branch head equals the checkout HEAD (says so on stderr), and the merge queue merges the resolved head (origin when the local ref lags it).
- `task new --scope` / `task set --scope` warn per scope entry that matches no tracked path at main's head (reports#125, reports#224); spawn-context repeats the warning in the agent brief. The stored comma list is echoed when it differs from the input, and the scope refusal lists the parsed entries one per line (reports#135).
- The subagent Bash guard no longer reads '>=' as a redirect (reports#150): SQL like `WHERE n >= 3` in a heredoc or quoted string fed to python or sqlite3 runs. No quote masking (D214); a plain '>' inside quotes is still read as a redirect. Known gap: '>' or '>>' directly followed by '=' is never read as a redirect, so a write to a file whose name starts with '=' is not refused (accepted for an accident guard).
- `evidence run` on Windows runs a `.sh` called by path through Git bash and records its real exit code and output (no more silent exit 0 or idle hang); a command that did not start records exit 127 with the reason, and exit 0 with empty output and no sign the process ran is recorded as refused (exit 125) (#241, aesir-reports #164).
- `task set N --status merged --landed` also accepts generated files (CLAUDE.md as regenerated by client tooling, ROADMAP.md, aesir-state/, .aesir-pkg/) and paths inside the task scope; other paths are refused by name with the `--scope` widening command and the no-code close path (reports#162, #154).
- `evidence run --expect-fail [--expect-exit K] [--expect TEXT]` gives a criterion that must fail (mutation check) real evidence: MET only when the command ran and failed as declared; an unexpected pass records NOT MET, and a missing tool (127), refusal (125) or timeout (124) never counts. README documents the temp-copy mutation pattern. Schema V24 adds `expect_fail` and `fail_met` to `evidence` (aesir-reports#163).
- A must-fail run (`--expect-fail`) may use a dirty `--dir`: the uncommitted mutation in a temp worktree at the task head is recorded at the unmutated head sha with a `dirty (mutation): <paths>` line, so the row is not stale. Without `--expect-fail` a dirty tree is still refused. README mutation pattern updated.
- Resume stale state, remainder of aesir-reports#136: a task left claimed/in_progress after its agent ended and its branch merged is one `done_task` line (shown once) with the `task set ... --status verified` command that closes it, not moved automatically; agents with no transcript (or a transcript silent for `no_agent_min` with a tool call open) are ended on resume and status instead of listed running; stalls idle over `stall_old_days` (aesir.toml [observe.aesir], default 7) are one count line in resume, and `status ack --older-than <days>` pauses them all at once (#246, aesir-reports #136).
- Generated agent files (aesir-reports#161): examples are single commands the hooks allow (no `cd X && ...`; the CLI is run by absolute launcher path), and the test-suite command in the implementer def comes from the client's `aesir.toml` [gates] at install/upgrade instead of Aesir's own. Re-run `upgrade` (or `upgrade --repair`) after changing the gate config to regenerate the defs.
- A spawn prompt's `Agent name: <x>` now names the agent row whatever its prefix (`checker-261` for a reviewer), for the PreToolUse Agent spawn as well as Workflow agents; the type stays recorded from the agent type. A near-miss `implementer-332a` (no dash before the letter) binds task 332, and `spawn-context` states the expected form `<role>-<task>-<letter>` (#248, aesir-reports #153). Role, scope checks, `--as` limits, re-spin supersede, friction/metrics buckets and context kind follow the agent type (`agent_role`), not the id prefix; a role or other type's name as prefix is refused. `spawn-context` and `agent list --role` find agents by type too.
- Task scope: `task new/set --scope` accepts comma- or space-separated entries and stores them comma-joined; scope checks also split old space-joined rows (#249, reports#135).
- No command creates a database outside a project any more: with no `.aesir/aesir.db` found from the cwd (and no `--db` / `AESIR_DB`) it refuses with `no Aesir project at <cwd>; run from the project or pass --db` and exits 1, creating no file. A project is a root holding `aesir.toml` or `.aesir-pkg` (or an existing db); a bare `.git` is not enough. Covers `release plan` and `upstream link/retry/sync-milestones` too.
- The client launcher `.aesir-pkg/aesir_run.py` run from a cwd outside any project uses the project holding its `.aesir-pkg` and says which on stderr. `upgrade` and `upgrade --repair` (re)write the launcher.
- `release` / `upstream fixed-in` no longer announce an issue as fixed while another linked task is still open: it is skipped as `partly fixed; open: #N` (aesir-reports#166).
- `task unlink N upstream <issue>` removes an upstream link (lead or the task's requester; logged in the task log).
- `upstream fixed-in vX.Y.Z --skip <issue>[,<issue>..]` leaves the named issues out and lists them as `skipped by hand`.
- Subagent Bash guard: `>|` (noclobber override) and ANSI-C, concatenated or otherwise quoted redirect targets (`> $'path'`, `> "a"/b`, `> $'E:/..'`) are read as one shell word with bash quote removal and refused into the main checkout like `>`; an undecodable target is refused, not skipped (aesir-reports#167, #261).
- `queue run` now holds a task whose branch adds a db migration while a running agent's worktree has fewer migrations than the branch would leave main with: the task stays queued (no failure, no attempt counted), the run skips it, goes on with later queue items, and lists a `held` result (exit 2) naming each agent, its worktree and migration count, and the commands to clear it (`agent end <id>` for a finished agent, then `queue run --once`). The hold clears by itself when those agents end or their worktrees reach the new schema. Lead-only `queue run --force-schema-hold --reason TEXT` merges anyway and logs the reason and the agents skipped on the task and as an event. Tasks that add no migration are never held. `skew.worktree_flags` takes an optional target count; `skew.migrations_in_text` reads a db.py from text (#266, aesir-reports #169).
- Subagent redirect guard: a `>` inside the body of a quoted-tag heredoc fed to cat or tee (e.g. `->` in a python f-string written with `cat > file <<'EOF'`) is no longer read as a redirect (aesir-reports #150 shape 2). Interpreter bodies, unquoted tags, piped heredocs and the redirect on the heredoc's own command line keep their verdicts.
- Subagent Bash guard (aesir-reports #150, #171, D221): a here-string (`<<<'EOF'`, `<<<"EOF"`) is no longer parsed as a heredoc, so the lines after it are judged; a command the parser cannot parse (unterminated quote or heredoc, heredoc tag built from glued pieces such as `<<'EO'F`) is refused once, up front, with a reason naming the cause and the fix; CRLF line endings with a plain `<<'EOF'` tag still parse. Known parser limits, refused for now and named in the refusal: a quote character inside a # comment, `$(( ))` arithmetic with `<<` (#271).
- Queue cleanup: when `git worktree remove` fails but git has already unregistered the worktree (Windows: the now-empty folder is in use by another process), the queue reports the note `worktree removed; empty folder left (in use): <path>; prune it later: python -m aesir worktrees prune` (result `notes`, not `problems`) instead of "left in place", and the merged branch is still deleted (Aesir #209 2026-11-02, aesir-reports #170; follow-up #263). A worktree git still lists keeps the "left in place" problem and its branch.
