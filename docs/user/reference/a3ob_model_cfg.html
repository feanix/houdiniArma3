Reference / Nodes

Model Cfg

Writes the model.cfg a character P3D needs (uniform, vest, headgear and other gear on the man skeleton) into a folder, or adds the P3D's class to the model.cfg that is already there. The messages show what Write model.cfg would do. The output is the input.

A character P3D (uniform, vest, headgear and other gear on the man skeleton) needs a model.cfg next to it. It holds the man skeleton and one class per P3D file name. This node writes that file into a folder, so you do not copy and edit it by hand.

Cooking only shows what Write model.cfg would do: the changes, any warnings and the whole text, as node messages. Write model.cfg then writes it. A model.cfg that is already there is updated in place: only the class of each model name is added or replaced (and Default, the base class and the skeleton if they are missing). Everything else in the file stays, and the old file is kept as model.cfg.bak. A binarized file, or a file that cannot be read, is refused with the line number.

Houdini namea3ob_model_cfg
Where to find itTab menu, A3OB, Model Cfg
Inputs0 to 1

Inputs

  1. Input 1: P3D geometry or LOD geometry (optional). Optional. Its selections are scanned for section names (Add Selections of the Input).

The node also works with no input connected.

Parameters

Parameters are in the order they appear on the node.

Folder folder

The folder to write model.cfg into. Normally the folder of the P3D, or a folder above it. The file is named model.cfg.

Type
Folder path
Default
(empty)

Model Names model

The P3D file names without .p3d, separated by spaces or commas. Each gets one class in CfgModels, named exactly like the file. Capitals matter to the build tools.

Type
Text
Default
(empty)

From P3D Export fromexport

Take Folder and Model Names from the Output File of the P3D Export node in this network (the one that shares this node's input, or the only one).

Type
Button

Base Class base

The CfgModels class that holds the shared settings and sections of man models. Each model class inherits from it. It is added when the file has none.

Type
Text
Default
ArmaMan

Skeleton skeleton

The CfgSkeletons class with the Arma 3 man skeleton (103 bones and their parents). It is added when the file has none; a class of that name that is there is kept as it is.

Type
Text
Default
OFP2_ManSkeleton

Extra Sections extra

More section names (selections that a config can retexture or hide, for example camo3), separated by spaces or commas. They are added to the sections of the base class, on top of the usual man list (camo, camo1, camo2, personality, hl, injury_*, insignia ...).

Type
Text
Default
(empty)

Add Selections of the Input scan

Also add the selections of the input geometry (visual LODs) that are not bones, proxies or a3ob_ helper groups, for example camo1. Off: they are only listed in the messages. Does nothing without an input. Check the list first: working groups of your own show up here too.

Type
On or off
Default
Off

Write model.cfg write

Create model.cfg, or update the one in the folder: only the model classes are added or replaced (and Default, the base class and the skeleton if missing). Everything else in the file stays. An old file is kept as model.cfg.bak. A binarized file or a file that cannot be read is refused.

Type
Button
